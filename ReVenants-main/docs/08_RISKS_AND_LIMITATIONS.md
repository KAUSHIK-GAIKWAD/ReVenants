# 08. Risks, Limitations, and Mitigations

Deploying an autonomous agent into peer-to-peer student communications carries real social, technical, and privacy risks. Below is an honest appraisal of our current system limitations and planned mitigations.

---

## 🛡️ Risk Matrix

| Risk Domain | Specific Failure Mode | Impact | Mitigation Strategy |
|-------------|-----------------------|--------|---------------------|
| **1. Intent Misclassification** | Marking a blocked task as `completed` because of positive keywords (e.g. "connected"). | False sense of security; team misses critical blockers. | Strict "Kabir Rule" in prompt, JSON schema validation, confidence scoring threshold (reject < 0.70), and one-click manual status override on web dashboard. |
| **2. Message Privacy** | Bot reading unrelated private or social chatter in a group chat. | Teammate privacy violation; loss of trust. | Bot only processes direct replies to its own messages or messages containing explicit `/status` or `@bot` mentions. All irrelevant messages are discarded and not logged to disk. |
| **3. API & Connectivity Outages** | Telegram webhook latency, Supabase connectivity, or Anthropic Claude API rate limiting/outage. | Bot fails to record status; updates get lost. | Retry buffer, exponential backoff retries, and offline fallback mode for local demos. |
| **4. "Spammy Bot" Fatigue** | Over-frequent automated pings cause students to mute or block the bot. | Teammates disengage completely from project updates. | Rate-limit check-ins to maximum once every 24 hours per task; implement "quiet hours" (no outreach between 11:00 PM and 9:00 AM); support `/snooze 24h` command. |
| **5. Hallucinated Deadlines** | Model generating incorrect due dates or attributing work to the wrong teammate. | Confusion across team members. | Task IDs and assignees are strictly looked up in Supabase, not generated by the LLM. The LLM only classifies the intent and blocker text. |
| **6. Escalation Boundaries** | Bot cannot force a student to complete work or resolve conflicts. | Stalled projects without human intervention. | When a task reaches `reminder_count >= 3` or remains `Blocked` for > 48h, the system escalates directly to the team lead via Telegram alert. |

---

## 🔒 Privacy & Data Retention Guidelines

1. **Minimal Data Storage**:
   - We store only messages directly associated with task updates.
   - We do not store student passwords, API keys shared in chat, or audio transcripts.
2. **Transparent Auditability**:
   - Teammates can view the full audit log on the web dashboard to see why the coordinator updated any task status.
   - Any team member can revert an inaccurate status update with a single click.
3. **Opt-Out & Mute**:
   - Any member can type `/pause` to temporarily disable automated bot check-ins for their tasks.
